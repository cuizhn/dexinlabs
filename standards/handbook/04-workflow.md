# Workflow

## 1. 文档定位

本文档定义得心实验室项目的标准开发流程。

所有功能开发、Bug 修复、重构和架构调整均应遵循本文档。

目标：

- 保持开发节奏一致；
- 降低多人协作成本；
- 保证 AI Agent 输出稳定；
- 避免未经思考的大规模修改。

---

# 2. 标准开发流程

所有开发遵循以下流程：

```
需求
 ↓
分析
 ↓
设计
 ↓
实现
 ↓
验证
 ↓
记录
```

任何一步都不应跳过。

---

# 3. 理解需求

开始开发前，应明确：

- 为什么要修改？
- 用户真正的问题是什么？
- 是否符合项目愿景？
- 是否已有类似实现？

禁止：

- 看到需求立即写代码；
- 未理解上下文直接重构。

---

# 4. 分析影响

修改前必须分析：

影响哪些模块？

例如：

```
Content Engine

↓

Markdown Engine

↓

Renderer

↓

UI
```

判断：

- 是否影响接口？
- 是否影响数据库？
- 是否影响已有页面？
- 是否影响其他模块？

---

# 5. 设计方案

优先：

小修改解决问题。

避免：

为了一个需求：

- 推翻已有设计；
- 新建大量抽象；
- 修改整个目录。

设计时应优先复用已有能力。

---

# 6. 实现

实现阶段遵循：

一次完成一个目标。

避免：

一次提交：

- 新功能；
- 重构；
- 修 Bug；
- 调整样式。

应保持修改范围尽可能小。
中大型任务必须先做 Context Audit

---

# 7. 验证

完成后至少验证：

## 类型

TypeScript 无错误。

---

## 构建

项目能够正常构建。

---

## 功能

新功能符合需求。

已有功能未被破坏。

---

# 8. 文档更新

涉及以下内容时必须更新文档：

- 架构变化；
- 数据模型变化；
- 新增规范；
- 新增模块；
- 重要设计决策。

保持文档与代码一致。

---

# 9. 重构原则

允许：

- 提高可读性；
- 消除重复；
- 修复设计问题。

禁止：

没有明确收益的大规模重构。

---

# 10. AI Agent 工作流程

AI Agent 修改代码前：

1. 阅读相关 Handbook。
2. 理解模块职责。
3. 分析影响范围。
4. 给出修改方案。
5. 再开始实现。

AI Agent 不应直接输出大量代码。

---

# 11. 问题处理原则

遇到问题：

优先：

定位原因。

然后：

修复根本问题。

避免：

增加特殊判断掩盖问题。

---

# 12. 提交原则

一次提交应只有一个目标。

例如：

✔ 修复 Lesson 页面布局

✔ 新增 Topic Service

✘ 同时修改十几个模块

---

# 13. 决策记录

以下修改需要记录 Decision Record：

- 修改架构；
- 新增核心模块；
- 更换依赖；
- 数据结构重大变化；
- 长期影响项目的设计。

---

# 14. 工作流优先级

始终遵循：

```
理解
↓

设计

↓

实现

↓

验证

↓

记录
```

不要把"写代码"作为第一步。
