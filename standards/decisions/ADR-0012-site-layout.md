# 给执行者：全局导航、首页与 Lesson 页面设计调整

请根据以下已确认的产品设计原则调整项目。

## 一、核心设计原则

本项目采用：

> **能不要就不要；主体在就行。**

页面只显示当前任务真正需要的信息。

尤其是 Lesson 页面：

> **Lesson 的任务是学习，不是展示网站导航结构。**

因此不要为了“完整”而增加 Breadcrumb、课程层级、课程编号、侧栏等 UI。

---

# 二、全局导航

网站不采用传统的：

```text
课程 | 练习 | 关于我们 | 方法心法 | ...
```

这种栏目式导航。

全局 Header 保持极简。

当前设计：

```text
得心实验室        搜索                         我的
```

具体视觉可以根据现有 Design / CSS 实现，但职责保持不变。

### Logo

点击进入首页。

### Search

作为全站知识探索入口。

当前第一阶段可以先实现基础搜索能力，不需要提前实现复杂的语义搜索。

未来搜索可以扩展到：

* Course
* Topic
* Lesson
* Concept
* Knowledge

但当前不要为了未来功能过度设计。

### 我的

目前用户系统尚未完成。

暂时只需要作为：

```text
我的
 ↓
登录 / 注册
```

入口。

不要提前设计：

* 学习诊断
* 学习进度
* 个性化推荐
* 学习能力
* 家长系统

这些属于后续阶段。

---

# 三、未登录首页

**当前阶段只设计未登录首页。**

暂时不要实现登录后的个性化首页。

未登录首页的核心任务：

> **让第一次来到得心实验室的人可以自由了解、自由探索，并尽快真正体验课程。**

Hero 应包含：

```text
得心实验室

理解，而不是记住。

[直接开始]

[注册 / 登录]

[深入了解]
```

具体文案可以根据现有产品文案调整，但交互职责保持一致。

---

## “直接开始”

必须是低摩擦入口。

用户点击后应该能够直接进入课程探索或课程学习。

不要增加不必要的：

* 登录要求
* 年级选择
* 教材选择
* 用户画像
* 学习诊断
* 多步骤 onboarding

第一阶段的核心目标是：

```text
进入网站
 ↓
看到课程
 ↓
进入 Lesson
 ↓
真正体验学习
```

---

## Hero 以下内容

未登录用户可以继续向下浏览。

首页不是单纯的 Landing Hero。

应该允许用户像“逛一个开放的知识空间”一样继续探索。

建议内容顺序可以考虑：

```text
Hero
 ↓
为什么是得心实验室
 ↓
课程 / 学习方式特点
 ↓
数学知识地图
 ↓
自由探索课程
 ↓
关于得心实验室
```

具体模块不要机械照搬。

原则是：

> 用户即使暂时不开始学习，也可以继续了解产品和知识体系。

不要通过注册墙阻止公开课程探索。

# 四、Lesson 页面

Lesson 页面采用**极简学习界面**。

不要使用：

* Breadcrumb
* `← 返回 Topic`
* `第 3 课 / 8`
* 固定 Topic 导航
* 固定 Chapter 导航
* 常驻 Learning Assistant
* 不必要的页面工具栏

---

## Lesson 页面默认结构

原则上：

```text
Global Header
        ↓
Lesson Content
        ↓
Next Lesson / Learning continuation
```

例如：

```text
┌──────────────────────────────────────────────┐
│ 得心实验室        搜索                   我的 │
├──────────────────────────────────────────────┤
│                                              │
│                                              │
│              为什么需要函数？                │
│                                              │
│              Lesson 内容                     │
│                                              │
│              Lesson 内容                     │
│                                              │
│                [知识点]                      │
│                                              │
│              Lesson 内容                     │
│                                              │
│                                              │
│                  下一课 →                    │
│                                              │
└──────────────────────────────────────────────┘
```

Header 保留全局入口，但 Lesson 自己不要再增加一套导航。

---

# 五、为什么 Lesson 不需要 Breadcrumb

不要因为：

```text
Course → Topic → Lesson
```

存在于信息架构中，就强制把它显示在页面顶部。

**信息架构 ≠ 页面必须显示的导航。**

用户如果需要离开 Lesson：

* 可以使用全局 Logo 返回首页
* 可以使用全局 Search 寻找其他内容
* 可以通过课程 / Topic 页面重新进入知识地图

因此 Lesson 不需要永久显示：

```text
数学 / 函数 / 第一课
```

也不需要：

```text
← 返回函数
```

---

# 六、“第几课”暂时删除

不要在 Lesson 右上角显示：

```text
1 / 8
```

或者：

```text
第 3 课
```

目前没有足够价值，而且会增加视觉噪音。

课程顺序应该由：

```text
Course / Topic / Chapter
```

等知识结构表达。

Lesson 页面主要表达：

> **我正在学习什么。**

而不是：

> **我在整个课程目录的什么位置。**

如果未来经过真实使用验证，发现学习者确实需要课程位置感，再重新设计。

---

# 七、知识点侧栏

这是 Lesson 页面目前唯一明确的“按需辅助信息”。

默认：

```text
Lesson
```

保持干净。

当用户点击 Lesson 中某个可交互知识点时：

```text
Concept
 ↓
打开侧栏
```

例如：

```text
┌────────────────────────────┬───────────────────┐
│                            │                   │
│       Lesson 内容          │      函数          │
│                            │                   │
│       ……                   │      定义          │
│                            │      相关知识      │
│                            │      ……            │
│                            │                   │
└────────────────────────────┴───────────────────┘
```

用户关闭以后恢复正常 Lesson。

**不要实现常驻右侧 Assistant。**

不要增加复杂的：

* AI 对话
* 自动提示
* 实时诊断
* 主动弹窗
* 智能推荐

这些以后有明确需求再做。

---

# 八、LessonAST 与这个设计的关系

Lesson 中的知识点不是普通文本。

如果 LessonAST 定义了：

```text
Concept
```

那么 Renderer 可以把它渲染成：

```text
可识别 / 可点击的知识点
```

点击后：

```text
Concept
 ↓
Concept Panel
```

因此：

> **AST 提供语义，UI 决定如何呈现和交互。**

不要为了当前侧栏 UI 而过度修改 LessonAST。

如果现有 AST 不足以支持这个行为，请先进行 Context Audit 并报告，不要自行修改核心 AST。
