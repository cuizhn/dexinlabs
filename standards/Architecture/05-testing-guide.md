# Testing Guide

## 1. 文档定位

本文档定义得心实验室项目的测试与验证规范。

测试目标不是追求高覆盖率，而是确保：

- 功能正确；
- 架构未被破坏；
- 修改不会影响已有能力；
- AI Agent 输出可验证。

所有开发完成后均应进行验证。

---

# 2. 测试原则

测试遵循：

```
正确性
↓

稳定性

↓

兼容性

↓

性能
```

任何修改都应至少验证正确性。

---

# 3. 修改后必须检查

每次修改至少完成：

## 类型检查

```
tsc
```

要求：

- 无 TypeScript Error。

---

## 构建检查

```
build
```

要求：

- 能正常构建；
- 无新增警告；
- 无运行时错误。

---

## 功能验证

验证：

- 当前需求已完成；
- 原有功能正常。

---

# 4. Service 测试

重点验证：

- 输入是否合法；
- 返回是否符合预期；
- 异常是否正确处理。

Service 应尽量保持纯函数特性。

---

# 5. Content Engine

检查：

- 数据是否正确加载；
- 查询是否正确；
- 返回结构是否稳定。

不得因为页面需求修改 Engine 行为。

---

# 6. Markdown Engine

重点验证：

- Markdown 是否正确解析；
- AST 是否正确转换；
- HTML 输出是否符合预期。

新增插件必须增加对应测试。

---

# 7. Renderer

Renderer 验证：

- HTML 正确显示；
- Slot 正常工作；
- 样式未破坏布局。

Renderer 不负责测试 Markdown 解析。

---

# 8. 页面验证

检查：

- 页面正常打开；
- 无控制台错误；
- 响应式布局正常；
- HTML 保持语义化。

---

# 9. 回归测试

修改核心模块后，应检查：

- Lesson
- Topic
- Domain
- Markdown Rendering

确认已有能力未受影响。

---

# 10. AI Agent 自检

AI Agent 完成修改后应确认：

- 是否符合 Handbook？
- 是否破坏模块边界？
- 是否新增重复代码？
- 是否影响其他模块？
- 是否需要更新文档？

如任一答案为"是"，应先处理，再提交修改。

---

# 11. 测试清单

提交前检查：

- TypeScript 无错误
- Build 成功
- 功能正常
- 无明显重复代码
- 文档已更新（如需要）
- Decision Record 已记录（如需要）

---

# 12. 测试原则

不要为了通过测试修改设计。

测试用于验证设计，而不是替代设计。
